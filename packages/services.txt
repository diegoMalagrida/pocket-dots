# The NVMe/VMD runtime-PM guard, whose .service and .path are in system/etc now.
# Without this line they sit on disk and nobody ever starts them, which is the
# same as not having the fix at all. The .path is the one to enable: it is what
# watches TLP and re-runs the .service every time TLP undoes the setting.
# Safe on a machine that is not this laptop: every ExecStart in the .service
# is '-' prefixed, so a device that is not there does not fail the unit. Two
# of the three name the Intel VMD domain (10000:...), which exists nowhere
# else; the third, 0000:00:0e.0, is an ordinary PCI address that another
# board may well have, and there it would simply pin that device's runtime
# PM on.
system		nvme-vmd-runtime-pm.path
